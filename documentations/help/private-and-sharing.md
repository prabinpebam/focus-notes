# Private notes and sharing

Keep notes private, publish them as web pages, and share any note with a link, a passcode or both.

> [!NOTE]
> **TL;DR.** **Share…** starts with the private note or folder you chose. Review its contents, choose how it opens, then copy its share information. Copying waits until the published encrypted share can actually be opened. Opening or cancelling the draft leaves existing shares unchanged.

## Review a note or folder

1. In **Files**, open the note or folder's row menu and choose **Share…**. For the note you're writing, use **⋯ → Note → Share…**. **Share…** is there for every note. If this project can't share yet, the dialog says what to do: turn sharing on, link the project to GitHub in **Settings → Project**, or move a standalone file into a project.
2. Check the item's name and, for a folder, its note and folder counts. **Review contents** opens a read-only tree; expanding a folder only changes the review.
3. Choose **Done** or press Escape to return to the same draft.
4. Choose the expiry and **Link** or **Passcode**. Link starts on, Passcode starts off, and **Include notes added later** starts off for folders. Both opening methods can be off, but that draft cannot be shared.
5. Close the dialog to discard the draft. No share or website is created by opening, reviewing or cancelling.

## Copy a share

Turn on **Link**, **Passcode**, or both. Passcode offers generated words or your own strong passcode. An access code combines a random identifier and the passcode; readers enter that single code without providing a person's name.

On Windows, choose **Copy share information**, **Copy link**, or **Copy access code**. The first action saves the share and waits for the website. Nothing is copied before the encrypted share is ready. The read-only **Share information** block then shows the actual message, written to the person you send it to and ready to paste. The note under it is for you: whoever gets the message can pass it on, and copies they download stay after the share expires or you withdraw it. On macOS, the primary **Share…** action opens the system share sheet instead.

**Sharing a published note.** A published note is already a web page anyone can read, so **Share…** on it offers only **Copy link**, which copies its web address. There's no encryption and no passcode.

**Publish and Unpublish.** **Publish** makes a private note a web page (it asks first). **Unpublish** takes the page down at the next publish and makes the note private again. Both are in the Files row menu and **⋯ → Note**. Sharing also puts a note on the website, but encrypted: it only opens with the link, the passcode or both.

Retrying a failed publication in the same dialog reuses the saved share. Opening **Share…** again starts an independent share; it does not replace the earlier link. With **Include notes added later** off, a folder share includes only the reviewed note identities, not another note later created at the same path.

**Not available yet:** shared-before actions, adding newer notes to an earlier share, first-site setup from this dialog and full review of very large folders. Change… and template editing aren't part of this dialog. Settings → Sharing remains available for existing named grants.
