Focus Notes

A calm, Markdown-native writing app: a blank canvas, one red trigger, and a focus mode that lights up only the line you're writing.

TL;DR

Notion/Loop-style editing (built on Tiptap) that saves plain Markdown to your own GitHub repository. You start in the browser: the web app runs from your own instance's GitHub Pages site, keeps what you write in that browser with no account and offline, and shows your public notes and, once you unlock them with your passphrase, your private ones, read-only. A desktop app (MIT-licensed Electron, with an invisible title bar, 20 px rounded on Windows and Linux, native on macOS), downloaded from GitHub Releases, is the only client that saves to GitHub, and it imports what you wrote in a browser (D-90). Every user's Focus Notes is their own instance in their own GitHub account: one repository with public notes, a private submodule, and a workflow that deploys the app to its own Pages, with nothing hosted by the project and no server. People who just want to use it copy the template repository (not the source repository) to make their instance; people who want to improve it fork the project repository. Until a browser unlocks a site's private notes, it sees only public notes and Use this app for yourself. Ctrl/⌘+/ opens Spotlight to find anything and act on it, and the keymap copies the apps people already use. Notes are private by default. They can be published on the user's own GitHub Pages site, or shared with named audiences through a magic link or a passcode. Agents can help through MCP and a command-line tool, within permissions the writer grants, and there is no telemetry. Every pixel comes from a strict design system, and the interface itself is data: JSON views built only from the system's components, with no HTML or CSS in the app. This site turns the human-written seed spec and the owner's later decisions into product, experience, architecture, and delivery documentation, and it's kept in step with the build. The plan has ten stages that each leave a usable app, each with a demo and a definition of done.

Signature experience

The blank canvas and trigger

Nothing but text, plus a red dot 10 px across in a frosted circle 30 px across that opens a toolbar of at most six actions.

Focus mode

The whole paragraph under the caret stays at full strength. Everything else is subdued.

Spotlight

Ctrl/⌘+/ finds notes, headings, text, settings, and commands, then acts on them.

Keyboard shortcuts

Four layers, from basic to pro, borrowed from the apps people already know, on macOS, iPadOS, Windows, and Linux.

The desktop app

A title bar that's invisible until you need it: 20 px corners with custom window management on Windows and Linux, a native window on macOS.

First run and sign-in

In the browser, nothing to set up: start writing at once, kept in that browser. On the desktop, sign in through Git's own tools and choose your vault passphrase.

Sharing with people

Share a private note or folder with someone by name, through a magic link or a passcode. It's published only as ciphertext and can be withdrawn at any time.

Agents and automation

A local MCP server, a command-line tool, deep links, and AGENTS.md. Agents get only the permissions you grant, and every change can be undone.

Design system

Tokens, primitives, layouts, and compound components, strictly layered. Views are JSON documents mapped onto them, so the app has no HTML or CSS of its own.

Plan and definition of done

Ten stages that each leave a usable app (M0, M1, MW, M3, M2, M4, M5, M7, M8, Later), 61 work packages in a machine-readable graph, an agentic build loop, and a measurable definition of done at every level.
