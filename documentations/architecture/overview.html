Architecture

Architecture overview

One web app core, two thin shells, and the user's own GitHub account as the only backend.

TL;DR

Focus Notes is a client-side app with no server of its own. The same web build runs inside an Electron desktop shell, which is the primary writing client (D-10), and from GitHub Pages in the browser. A shared core (Tiptap editor and block registry, focus mode, theme engine, command and keybinding service, Spotlight index, workspace) talks to storage through one workspace adapter interface. The desktop runs the user's own git on a local clone, signed in once through Git's own sign-in helper (Git Credential Manager or the GitHub CLI, with a device code) or a token the user creates. The web build uses the GitHub REST API (M6). All of a user's content lives in their two GitHub repositories, a public notes repository and a private one mounted as a submodule, and publishes to their GitHub Pages. The project registers no OAuth app and runs no server (D-21, D-38). Everything is MIT-licensed or uses a compatible license.

Layers

Shells
Startup, window chrome, and access to platform services. The Electron shell adds the window (native on macOS; a frameless 20 px-rounded window with app-built window management on Windows and Linux) with a custom title bar, a native menu bar on macOS, file-system access, sign-in, and Git, all exposed through a narrow, typed preload bridge (Desktop and Git, Desktop app). The web shell is a static page.
Editor engine and block registry
The Tiptap block editor, Markdown parse and serialize, input rules, find and replace, and the plugin registry for block types (Editor engine).
Commands and keybindings
Every action is a named command. The keybinding service maps keys to commands by context and platform, and feeds the toolbar, ⋯ menu, macOS menu bar, cheat sheet, and Spotlight (Keyboard shortcuts).
Spotlight and search index
A MiniSearch index in a Web Worker covering notes, headings, full text, folders, commands, and settings. It's kept on the device only (Spotlight).
Focus mode
A self-contained module that watches the editor's selection and writes the mask band (Focus mode).
Design system and UI runtime
Tokens, primitives, layouts, and compound components in packages/ui, and the renderer that turns JSON view documents into the interface, binding them to view models and commands. No other code renders markup or styles (Design system, D-56, D-57).
Theme engine
Loads, validates, and merges theme JSON, then applies tokens as CSS custom properties (Theming).
Workspace
The note tree, file operations, visibility, sharing, the save queue, and conflict handling (Files and sharing). It is the only module that talks to an adapter.
Workspace adapter
One interface with two implementations. The operations are: list a tree, read a note (with its version), write a note against an expected version, move, delete, commit a batch, and read history. Each operation is told which repository it targets: public or private.

No OAuth app, no server

An OAuth app would need the project to register it, and browser sign-in would also need a token-exchange server. Both are ruled out (D-21). So the desktop app asks Git, and Git uses whatever sign-in helper the user has installed (Git Credential Manager and the GitHub CLI both offer device codes). In the browser, the user pastes a fine-grained token created from a pre-filled GitHub link. Every credential belongs to the user and lives on their computer.

Security baseline

  • The interface is rendered only from validated view documents through a closed component registry. No code path sets innerHTML.
  • A strict Content Security Policy: no inline scripts, and connections only to api.github.com and the app's own origin.
  • Markdown is sanitized when rendered, both in the editor and on published pages. Raw HTML in notes is shown as text, not run.
  • Access tokens never go into the repository, URLs, process arguments, or logs. In Electron they go in the OS's secure storage and git's credential helper (never the plaintext store helper). On the web they are held in memory, with an optional encrypted local copy.
  • Private note content only reaches the GitHub Pages artifact in sealed (encrypted) form (see threat model).
