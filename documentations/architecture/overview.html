Architecture

Architecture overview

One web app core, two thin shells, and GitHub as the only backend.

TL;DR

Focus Notes is a static, client-side web app. The same build runs in the browser from GitHub Pages and inside an Electron shell. A shared core (editor engine and block registry, focus mode, theme engine, workspace) talks to storage through one workspace adapter interface. The web uses the GitHub REST API; Electron uses a local Git clone. All content lives in two GitHub repositories, a public one and a private one mounted as a submodule. There is no proprietary server.

Layers

Shells
Startup, window chrome, and access to platform services. The web shell is a static page. The Electron shell adds a frameless window, native menus and shortcuts, file-system access, and Git, all exposed through a narrow, typed preload bridge with context isolation turned on.
Editor engine and block registry
The WYSIWYG block editor, Markdown parse and serialize, input rules, and the plugin registry for block types (Editor engine).
Focus mode
A self-contained module that watches the editor's selection and writes the mask band (Focus mode).
Theme engine
Loads, validates, and merges theme JSON, then applies tokens as CSS custom properties (Theming).
Workspace
The note tree, file operations, visibility, sharing, the save queue, and conflict handling (Files and sharing). It is the only module that talks to an adapter.
Workspace adapter
One interface with two implementations. The operations are: list a tree, read a note (with its version), write a note against an expected version, move, delete, commit a batch, and read history. Each operation is told which repository it targets: public or private.

Why no OAuth button on the web, at first

GitHub's OAuth token exchange needs a client secret and can't be called from a browser page. A purely static GitHub Pages app therefore can't finish a standard OAuth sign-in without a small token-exchange service. The first release uses a scoped personal access token so it needs no server. Adding a tiny token-exchange function later is tracked as decision D-02.

Security baseline

  • A strict Content Security Policy: no inline scripts, and connections only to api.github.com and the app's own origin.
  • Markdown is sanitized when rendered, both in the editor and on published pages. Raw HTML in notes is shown as text, not run.
  • Access tokens never go into the repository or into URLs. On the web they are held in memory, with an optional encrypted local copy. In Electron they go in the OS keychain.
  • Private note content only reaches the GitHub Pages artifact in sealed (encrypted) form (see threat model).
