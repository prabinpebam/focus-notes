# Decisions

Every assumption and design choice these docs make beyond the literal [seed spec](../seed-specs.md), in one place, so any of them can be revisited deliberately.

> [!NOTE]
> **TL;DR.** 74 decisions. D-01 to D-44, D-56, D-57, and D-73 are settled by the owner. D-45 to D-55, D-58 to D-72, and D-74 are proposals that stand as the plan until changed. **D-56/D-57**: a strict, layered design system, and an interface defined entirely as data, with no HTML or CSS in the app. The newest owner decisions: **D-41/D-42**: private sharing with named audiences through magic links and passcodes, in the first release. **D-43**: download first, browser second. **D-44**: agent-friendly through MCP, a command-line tool, deep links, and AGENTS.md. Key owner decisions: **D-14**: 20 px corners on Windows (and Linux) by drawing the window and rebuilding window management; macOS uses its native window. **D-16**: Spotlight is <kbd>Ctrl/⌘</kbd>+<kbd>/</kbd>, and <kbd>Ctrl/⌘</kbd>+<kbd>K</kbd> is the link key. **D-19**: support every platform possible. **D-21**: no OAuth app, no registration, and no hosting by the project. Sign-in goes through Git's own sign-in tools that the user owns (with device codes), and each user's Focus Notes is an isolated instance in their own GitHub account (**D-38**). The owner accepted every remaining proposal on 2026-10-13.

## Licensing policy (D-20 details)

| Class | Licenses | Rule |
| --- | --- | --- |
| Allowed | MIT, ISC, BSD-2-Clause, BSD-3-Clause, 0BSD, Apache-2.0, Unlicense, CC0-1.0, and OFL-1.1 for fonts (D-29) | Can ship. Keep their notices in a generated `THIRD_PARTY_NOTICES`. |
| Case by case | MPL-2.0, CC-BY-4.0 (icons and other assets), CC-BY-3.0 (the EFF wordlist, D-52) | Needs a recorded decision here. |
| Not allowed | GPL, LGPL, AGPL, SSPL, BUSL, any proprietary or paid license (including the paid Tiptap bundles) | CI fails the build. |

A license check runs in CI from M0 onward. Development-only tools follow the same list, unless their output never ships. Tools the user installs themselves (Git, Git Credential Manager, GitHub CLI) aren't shipped, so they aren't covered.

## Changing a decision

A change starts here, then follows [the articulation chain](../product/spec/chain.md): update the affected promise, scenario, or user-can first, then the views, components, and requirements that trace to it.
