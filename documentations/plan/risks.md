# Risks

What could make Focus Notes fail, how likely and how bad each risk is, and what the plan does about it. Review this register at the end of every milestone.

> [!NOTE]
> **TL;DR.** The biggest risks are **scope** (a large product for a small team), the **custom window management on Windows**, **Markdown round-trip fidelity** with a rich editor, **supply-chain trust** (users' *Deploy app* workflows deploy the project's released bundle with their secrets present), **share passcodes and the vault passphrase** that can be attacked offline, **notes kept only in a browser** being lost or never reaching GitHub, **onboarding friction** (Git, sign-in helpers, and unsigned builds for the desktop app, the only way to save to GitHub), **dependence on GitHub**, **the cost of running Git** for every view, and the **data-driven interface** turning into an inner platform or slowing feature work. Each has a mitigation and an early check in the roadmap.

| --- | --- | --- | --- | --- | --- |
| R-01 | **Scope is large for a small team.** Version 1.0 includes the web app (browser notes, read-only instance notes, and the vault), the desktop app's sign-in and Git, files, publishing, and sharing (D-85, D-90). | High | High | The milestones each ship something usable. P1 items are strictly deferred. Cut candidates are listed in the roadmap's definition of done. | Every milestone |
| R-02 | **Custom window management on Windows feels non-native** (resize jitter, DPI bugs, snapping fidelity, accessibility of the custom controls). | Medium | High | The M0 spike across Windows 10, Windows 11, and Ubuntu with mixed-DPI monitors. | R-03 | **Markdown round-trip fidelity** with a rich editor (whitespace, list markers, escapes, tables) | High | High | The byte-for-byte corpus from M0. Untouched blocks are written back from their source text. Constructs that can't be kept are preserved as raw blocks. | M0, M1 |
| R-04 | **Supply-chain compromise** of the *Deploy app* workflow, the web app bundle, or the desktop releases, which run with users' secrets | Low | Severe | Pinned commit SHAs, pinned versions, checksums, attestations, signed builds, updates by pull request only, a release environment with a required reviewer and a `v*` tag policy (repository settings, D-128), two-factor authentication on the maintainer account | M0, M5 |
| R-05 | **Share passcodes or the vault passphrase cracked offline** (static hosting can't rate-limit, and the vault's keyring is published with every deploy) | Medium (for weak passcodes) | High | Generated passcodes by default, a strength check for custom ones, PBKDF2 at 600,000 iterations, expiry by default. | R-06 | **Onboarding friction:** copying the template and turning on Pages; then, to save to GitHub, the desktop app: no Git, no sign-in helper on macOS or Linux, unsigned-app warnings, and choosing a vault passphrase | High | Medium | The browser needs no setup at all (D-90), clear steps in *Use this app for yourself* and the README, install help in the desktop first run, three sign-in paths, signing budget planned before 1.0 | MW, M3, M5 |
| R-07 | **Git conflicts and repository states** confuse non-technical writers, or lose work | Medium | High | Note-level conflict choices, never leaving a rebase half-done, the recovery journal, Recently deleted, and integration tests for every repository state | M2, M3 |
| R-08 | **Dependence on GitHub:** API or Pages changes, rate limits, account suspension, the 60-day schedule rule | Medium | High | Plain Markdown in Git means any Git host keeps the notes readable. Conditional API requests and backoff. Keepalive warnings. GitHub.com only is a documented boundary (UNSUP-PLAT-01). | Ongoing |
| R-09 | **Private-note leaks** through publishing, XSS, or agents | Low | Severe | Leak check on every deploy, sanitization and CSP, agents denied private access by default, security review before 1.0 | M5, M7 |
| R-10 | **Prompt injection through note content** leads an agent to misuse its tools | Medium | Medium | No destructive or sharing tools, content labeled as data, attribution, and Undo | M7 |
| R-11 | **The public instance repository reveals metadata** (the private repository's name, publish times) | Certain | Low | Documented in the privacy commitments. The private repository can have any name. | M5 |
| R-12 | **Electron size, memory, and battery** expectations | Medium | Medium | Performance budgets enforced in CI by `pnpm bench --check`, no polling, lazy-loaded views, a warm-up that yields to typing | M1 onward |
| R-13 | **Licensing changes upstream** (for example Tiptap) | Low | Medium | Pinned versions (MIT releases stay MIT), the license check in CI, a plain ProseMirror fallback | Ongoing |
| R-14 | **Accessibility gaps** in custom widgets (the trigger, tables, window controls) | Medium | High | ARIA Authoring Practices patterns, automated and manual screen-reader passes every release | M1 onward |
| R-15 | **Workspace format drift** between app versions on different computers | Medium | Medium | `formatVersion`, migrations, and older apps refusing to write newer formats | M2 |
| R-16 | **The view format becomes an inner platform**: views need logic the format can't express, and pressure builds to add scripting | Medium | High | Logic belongs in view-model selectors and commands by design. The expression subset is fixed and growing it needs a decision. The M0 spike builds the three hardest views (Settings, Files, Spotlight) before the format is frozen. | M0 |
| R-17 | **Strictness slows feature work**: every new look needs a component change | Medium | Medium | A short component process, a broad initial catalog, variants before new components, and the gallery so changes are cheap to review | M1 |
| R-18 | **Renderer overhead** on large views | Low | Medium | Per-field subscriptions, virtual lists, fragments expanded at build time, the typing path outside the renderer, and DSY-11 budgets measured in the M0 spike | M0 |
| R-19 | **Git process cost makes the app feel slow**, especially on Windows, where each process costs about 80 ms and a dozen status questions per view add up to seconds | High | High | One cached `git status` per repository, run in parallel, that no view waits for (D-66). Structural changes shown before the commit (D-68). The benchmark counts Git processes per interaction and fails CI on a regression (D-65). | M0, M3 |
| R-20 | **Notes kept only in a browser** are lost when the site's data is cleared, or never reach GitHub because the desktop app isn't installed (D-90) | Medium | High | Persistent storage (`navigator.storage.persist()`), a plain warning in the welcome note, *Export my notes*, and the desktop app's import, which deletes nothing on either side (PKG-07, PKG-11, FRE-10) | MW, M3 |
| R-21 | **A forgotten vault passphrase, or a remembered vault key on a shared `github.io` origin** (D-90) | Medium | Medium | Setup says a forgotten passphrase can't be recovered and the notes stay in the private repository; *Remember on this browser* is opt-in, non-extractable, and warns, with a custom domain recommended (SEC-08) | MW |
| R-22 | **Git inside a folder another service syncs** (OneDrive, Google Drive, iCloud, Dropbox) breaks the repository: the service copies `.git` file by file, mid-write, and makes conflict copies of Git's own files (D-215) | High (if allowed) | High | No `.git` in a synced folder by default, a warning before *Use it anyway*, and new GitHub folders kept out of a synced Documents (`%USERPROFILE%\Focus Notes`) (FRE-15) | M5 |
| R-23 | **Online-only notes and held files** in a synced folder: reading titles downloads every note, and a save fails while the service holds the file | Medium | Medium | Titles from file names for online-only files, search skipping them until opened, a save retried for up to 5 s with the wait shown, and the journal keeping the text meanwhile (FRE-15) | M5 |
| R-24 | **The notes folder moves under the app**: Windows moves Documents into OneDrive (Known Folder Move), a drive letter changes, or the folder is renamed | Medium | High | The start check before anything else, *Find the folder…*, the known OneDrive Documents path tried by itself, and a folder put back opening by itself (FRE-11, FRE-12) | M5 |
| R-25 | **Notes deleted outside the app are backed up as deletions** (the folder emptied by mistake, a sync service removing files), and GitHub then loses them too | Low | Severe | Backup pauses with an alert when more than 20 notes, or more than half, disappear outside the app; nothing is lost from Git's history; *Recently deleted* and the history keep every version (FRE-13) | M5 |
| R-26 | **The Store package's own Git falls behind** on security fixes, because it changes only when a release updates the pin, while a system Git updates on its own | Medium | High | Pinned by SHA-256 to GitHub Desktop's build, which follows Git for Windows' releases; `node tools/release/git-bundle.mjs --latest` names a newer one and every Store release checks it before building (PKG-13, D-228) | M5 |
| R-27 | **A rewrite discloses note text or incurs unexpected cost.** No provider is approved today; a loopback URL is not proof of local inference. | High | Severe | D-236/D-238/D-239 are Proposed (owner); named destination, private per-use consent, size/token/day limits, unknown-price label, no fallback. Cheapest check: offline egress/consent/cap matrix has zero unapproved sends. Owner resolves gate before real transport. | MAI, WP-AI.6 and WP-AI.7 |
| R-28 | **Streaming, review autosave, crashes or concurrent edits lose the original.** | Medium | Severe | Durable checkpoint before first token; hold save/commits through review; guarded source-aware splice and conflict lane. Kill at every state and alter disk/other window; both original and outside edits must remain recoverable. Failure blocks apply, not writing elsewhere. | MAI, WP-AI.1 and WP-AI.5 |
| R-29 | **Note prompt injection or generated active content leaks data.** | High | Severe | Target is data, no tools, validated supported Markdown, no generated-resource fetch. Injection/malformed/refusal fixtures must produce zero calls outside the approved operation and no active HTML. | MAI, WP-AI.1 and WP-AI.6 |
| R-30 | **Variation history bloats storage or leaks through workspace mirror pushes.** | Medium | Severe | Isolated local-only storage, private partition, bounded retention, neutral messages, mirror-push object inspection; unresolved checkpoints cannot be evicted. Cheapest check before UI: sentinel fixture proves no variation objects in a pushed workspace. | MAI, WP-AI.4 |
| R-31 | **Store capabilities and public privacy claims no longer describe optional egress.** | Medium | High | Plan, do not edit claims now. WP-AI.7 records capability/privacy scope; WP-AI.8 changes approved claims together with controlled rollout; no claim of local-only inference from URL alone. | MAI gate |
| R-32 | **Desktop-only rewrite is mistaken for browser support.** | High | Medium | Explicit web exclusion, absent browser command/setup and version-specific Help. WP-AI.10 proves the boundary and records secure-adapter prerequisites before any web implementation. | MAI, WP-AI.10 |
| R-33 | **Moving the familiar link key surprises writers or breaks table/Spotlight scopes.** | High | Medium | Mod+Shift+J checked free in current registry/catalogue; scoped Spotlight Mod+K unchanged; one-time hint, all menus/Help/cheat sheet/tests migrate at release. ## Rewrite assumptions to validate

All are hypotheses, not research outcomes. See [decisions](decisions.md#rewrite-with-ai-decisions-30-october-2026).

| Hypothesis | Evidence now | Cheapest check and criterion | Decision changed by failure |
| --- | --- | --- | --- |
| A-RWR-01: a protected inline suggestion is easier to judge than a separate diff. | Owner requests inline prompting; no usability test. High impact, weak evidence. | Fake-provider prototype: owner completes prompt/compare/discard unaided in 2 minutes and can identify the original. | Revise preview model before real adapter work. |
| A-RWR-02: one OpenAI-compatible contract is sufficient for the first approved destination. | Starting architecture hypothesis; catalogue is not a live certification. High impact, weak evidence. | Offline operation fixtures prove all event/error/cancel paths; owner-selected adapter must pass the same contract before enablement. | Add a separately gated adapter or narrow supported endpoints; never silently degrade. |
| A-RWR-03: source-aware partial mapping preserves exact outside bytes. | Existing round-trip requirement, not proof for rewrite. High impact. | Corpus includes every listed selection shape and verifies byte hashes; unsupported shapes must explicitly expand or refuse. | Reduce selectable scope before risking data. |
| A-RWR-04: retained local history is useful at 20 variations/30 days/100 MiB. | Proposed bounds, no usage data. Medium impact. | Synthetic cap/eviction/restart fixture proves originals cannot be evicted; owner tries finding a prior session. | Adjust local-only retention through a decision, not telemetry. |
