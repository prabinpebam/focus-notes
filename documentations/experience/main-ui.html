Main UI and the trigger

A blank canvas with one red dot. Everything that isn't writing lives behind it.

TL;DR

The window shows only the note and the trigger: a red dot 10 px across inside a frosted circle 30 px across, at the top center, 40 px below the window's top edge (owner decisions D-03 and D-78). Pointing at it grows the dot to fill the circle. Activating it opens a minimal toolbar that shows at most six actions (New, Open, Search, Save, Focus, Theme). Everything else goes into a ⋯ menu in the seventh slot; in the browser it also has Export my notes…, Import notes…, and Unlock private notes… or Lock. In the browser, notes written there are editable and kept in that browser, and the instance's own notes open read-only with a quiet Read only · Copy to my notes pill (D-90). Until a browser unlocks the owner's private notes it shows the visitor view, with a quiet Use this app for yourself in the bottom-left corner. A faint account pill in that corner shows the GitHub login on the desktop, and Unlock or the owner's name in the browser (UI-12). Formatting controls appear only in context, and Spotlight (Ctrl/⌘+/) reaches every command. Covers UI-01 to UI-10 and UI-12 in the requirements.

The canvas

The canvas is the whole window. At rest it shows the note's text and the trigger (UI-01), and, where they apply, faint pills in the bottom-left corner (UI-12).

  • No persistent chrome. No sidebar, tab strip, visible title bar, status bar, or word count. On the desktop, the top 44 px are an invisible title bar for dragging the window, and the window controls appear only on hover (see Desktop app).
  • Reading column. Text sits in a centered column. Its width is a theme token (layout.measure, default 70 characters) so line length stays comfortable on wide screens.
  • Top clearance. The column starts below the 44 px top band, so the trigger never covers text at scroll position zero. Scrolled text passes under the trigger and is blurred by it, which is why it's frosted rather than opaque.
  • Empty note. A new note shows one placeholder line in the subdued text color: "Start writing, type / for blocks, or press ⌘/ or Ctrl+/". Nothing else appears.
  • Account pill (UI-12, D-89, D-90). In the bottom-left corner, a small pill in muted caption text with no fill, barely there until pointed at.
    • Desktop: the GitHub login Git is signed in as, @login, with · Not synced after it while saving to GitHub has a problem. Pressing it opens a small menu: the sync status (Saved to GitHub or Not synced yet), Sync now (the same as Save), and Sign out of GitHub, which asks first whether Git's sign-in on this computer (the terminal's) goes too (FRE-07, D-103). It's checked once the workspace is a Git repository, never before the first frame, and is hidden when Git isn't signed in (D-101).
    • Browser, site with private notes: a quiet Unlock link that opens the passphrase dialog (Web app → Unlocking private notes). Once unlocked it shows the owner's name, and its menu offers Lock and Forget this browser.
    • Hidden where neither applies (a browser on a site without private notes).
  • Use this app for yourself (PKG-09, DST-01). In the browser, until it's unlocked, a quiet button in the same corner, beside the account pill, opens the dialog about getting your own instance. It goes away once the browser is unlocked, and the desktop app never shows it.
  • Read-only marker (PKG-08). In the browser, a public or private note of the instance opens read-only, with a quiet pill in the bottom-left corner: Read only · Copy to my notes. Pressing it copies the note into this browser's notes and opens the copy. The note's text can be selected and copied, but not changed.
  • Save state is never a permanent indicator. See trigger states for how unsaved or failed saves surface.

The trigger

The trigger is the app's only permanent control and the visual entry point to every app-level action (UI-02, UI-03).

Dot
10 px diameter, solid red. The color is a theme token, so a theme can retune the exact red but not remove it.
Frosted circle
30 px diameter (15 px radius), centered on the dot. Translucent surface with backdrop-filter: blur() (the "frost"). It has a hairline edge so it stays visible on blank backgrounds in both light and dark themes.
Position
Fixed, horizontally centered, and vertically centered in the top 44 px band (in the title bar on the desktop). It stays in place while the note scrolls.
Hit area
The visible circle is smaller than the 44 px minimum for touch targets, so an invisible 44 × 44 px area around it takes the clicks and taps. The focus outline is drawn around the visible circle.
Semantics
A button named "Open toolbar", with aria-expanded and aria-controls pointing at the toolbar.

The minimal toolbar

The toolbar is a small frosted panel that opens directly under the trigger. It holds app-level actions only (UI-04). Text formatting never goes here. The rule is six actions at most; everything else lives in ⋯, the seventh slot (owner decision D-26).

Items that toggle show their current state, for example a check next to the active theme. Choosing an item closes the menu, and the caret goes back to the note. The menu also shows each shortcut, so it doubles as a way to learn them.

As built through M1 (D-100): the groups are View (text size, Font ▸, Full screen), Theme (System, Light, Dark, Light theme ▸, Dark theme ▸), Edit (Find, Find and replace, and, from M4, Find in all notes, D-110), Note (Share and visibility…), and App (Settings, Keyboard shortcuts, Help and docs), with the browser's Your notes group before App. An item whose feature comes in a later stage is there but unavailable, with the reason under its label ("Sharing and visibility arrive in a later preview"). The arrow keys still reach it, so a screen reader reads it with its reason; choosing it does nothing and keeps the menu open. The Note group's other items and About join as their features are built. In a narrow window a submenu opens below its item instead of beside the menu.

The visitor view

Until a browser unlocks the instance's private notes, it shows the visitor view, for anyone, the owner included (PKG-09, D-90). The instance's public notes open read-only: Open lists them beside the notes written in this browser, and Focus, Theme, and the ⋯ menu's View items work as usual. Anyone can still write their own notes, kept only in their own browser, so New and Save work on those. The Note group's editing items don't apply to read-only notes, which offer Copy to my notes instead. A quiet Use this app for yourself in the bottom-left corner opens a dialog explaining how to get your own instance or download the desktop app (DST-01).

Behavior

  1. Open

    Click, tap, Enter or Space on the trigger, or Mod+. (also F10 on Windows and Linux). The frosted circle morphs into the toolbar: it widens into the toolbar's shape over 300 ms while the red dot shrinks and fades, and the buttons fade in 150 ms later. Closing plays it in reverse. With reduced motion it switches at once. Focus moves to the first action, or to the one used last if the toolbar has been used (UI-10, D-78, D-100).

  2. Navigate

    Arrow keys move between actions (one tab stop for the whole toolbar). Home and End jump to the first and last. ↓ or Enter on ⋯ opens the menu.

  3. Act

    An action either finishes at once and closes the toolbar (New, Save, Focus, Theme), or replaces the toolbar with its own panel (Open, Search, ⋯ items such as Settings).

  4. Dismiss

    Esc, clicking outside, or running an action closes every panel and puts the caret back exactly where it was.

Design rule

A new feature gets a toolbar slot only by taking one of the six. Everything else goes in ⋯, a contextual control, a shortcut, or Spotlight.

Contextual editing UI

Text-level controls show up only when they apply and fade away when they don't (UI-06). Behavior is on Editing. Detailed design is on Text formatting.

Formatting toolbar

Appears above a non-empty text selection: bold, italic, strikethrough, code, link, and turn into.

Slash menu

Typing / opens a filterable list of every registered block type.

Block handle

Appears in the left margin on hover or keyboard focus. Drag to reorder, or click for block actions.

Accessibility

  • The trigger, every toolbar action, and every ⋯ item can be reached and operated with the keyboard alone, and each has a visible focus indicator (UI-05).
  • The trigger has an accessible name and announces its expanded state, and that it opens a dialog (the toolbar's panel). The toolbar uses the toolbar role and ⋯ uses the menu pattern. Panels return focus to the editor when they close.
  • Every control is at least 24 × 24 px, tooltips opened by keyboard focus stay inside their control's landmark, and everything reflows at 320 px (WCAG 2.5.8, 1.4.10). See the accessibility audit.
  • The frosted circle keeps at least 3:1 contrast against the canvas in every theme. The red dot is never the only signal for any state.
  • All motion respects prefers-reduced-motion.
