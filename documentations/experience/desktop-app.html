Experience

Desktop app

A borderless window with 20 px corners, a title bar you can't see until you need it, and the trigger sitting in the middle of it.

TL;DR

The Electron app is the main writing client (D-10). Its window has 20 px rounded corners and a custom title bar: the top 44 px are a drag area with the trigger centered in it, and the window controls appear only on hover or keyboard focus. Getting exact 20 px corners needs a transparent window. Electron documents that such windows lose native resizing, double-click maximize on Windows, and the macOS shadow, so the app provides all of those itself (D-14, open). Covers DSK-01 to DSK-07 in the requirements.

Window shape

  • 20 px corners (owner decision D-24), clipped cleanly with anti-aliased edges in both themes. The value is the window.radius token.
  • Square when it touches the screen edges: radius 0 when maximized, snapped to a screen edge (Windows), or full screen, matching how native windows behave.
  • Linux without a compositor can't draw transparency. There the window falls back to an opaque, square frameless window with the same title bar.
  • The canvas inside is the theme's opaque canvas color. The desktop behind the window is never blurred through it, which keeps text contrast predictable. The "frost" is used only on the trigger and the panels.

How the corners are made

Native window corners can't be set to 20 px. Windows 11 offers only its own rounding (about 8 px) or none, and macOS draws its own radius. So the window is created transparent and frameless, and the 20 px shape is drawn with CSS. Electron's documentation lists what that costs. Each cost has a counter-measure:

Documented limitation of transparent windowsCounter-measure in Focus Notes
Not natively resizableThe app draws its own resize handles: 6 px edges and 14 px corners on all sides. Dragging updates the window bounds once per animation frame. Minimum size is 480 × 360.
On Windows, can't be maximized from the system menu or by double-clicking the title barThe app handles double-click itself and the maximize button calls maximize and restore directly. On macOS, double-click follows the user's system setting (zoom or minimize).
No native shadow on macOS (and none on Windows with transparency)A soft CSS shadow is drawn in a 16 px transparent margin around the window. That margin passes clicks through to whatever is behind it, using forwarded mouse events, so it never blocks other apps. The margin disappears when maximized or full screen.
Can't click through transparent areasHandled by the click-through margin above.
Not transparent while DevTools is openDevelopment only. Doesn't matter in release builds.

Spike first

M0 includes a window spike on Windows 11, macOS, and Ubuntu that tests: smooth resizing from every edge, maximize and restore, Win+arrow snapping, moving between monitors with different scaling, the shadow, and the click-through margin. If resizing doesn't feel native, the fallback is native corners. That trade-off is open question D-14.

Title bar

Band
The top 44 px of the window. It's invisible: the same color as the canvas, with no line under it. When the note scrolls, its text passes under the band and the frosted trigger.
Drag
The whole band is a drag region (-webkit-app-region: drag), except the trigger, the window controls, and any open panel.
Trigger
Centered in the band and vertically centered in it (see Main UI). This is its only position, and it doesn't move when the window is resized.
macOS controls
The native traffic lights (the title bar style is hidden), placed 18 px from the top-left corner so they sit comfortably inside the 20 px curve. They're hidden at rest and appear when the pointer enters the band, when the toolbar is open, or when the window isn't the active one. The window-button visibility setting does this.
Windows and Linux controls
Minimize, maximize/restore, and close, drawn by the app at the top right in theme colors, with a red hover state on close following the Windows convention. They follow the same show-on-hover rules as on macOS. They're real buttons that can be focused and have accessible names. Electron's native title-bar overlay can't be used with transparent windows, so the Windows 11 Snap Layouts flyout isn't available (D-15).
Keyboard
Every window action is also a command: > Minimize window, > Maximize window, > Close window, > Toggle full screen, with the usual shortcuts (App and window).

Window behavior

BehaviorSpecification
Full screen⌃⌘F (macOS, native full-screen Space) or F11 (Windows, Linux). Corners and the shadow margin go away. The title bar band collapses and comes back when the pointer reaches the top edge. The trigger stays visible.
Remembered stateSize, position, maximized and full-screen state are remembered per window and restored at launch. A window that would open off-screen (for example after a monitor is unplugged) is moved onto the nearest display.
Multiple windows (P1)One note per window. Mod+Shift+N opens a new one. Spotlight's alternative action (Mod+Enter) opens a note in a new window.
MenusmacOS: a full native menu bar at the top of the screen lists every command and shortcut. Windows and Linux: no menu bar. Commands are in the toolbar, the ⋯ menu, Spotlight, and context menus.
External linksOpen in the default browser. The app window never navigates away from the app.
Single instanceOpening the app again focuses the existing window instead of starting a second copy.

Light, dark, and system

The window follows the same three-way theme choice as the rest of the app (Theming): System (default, follows the OS live), Light, or Dark. The native parts (macOS traffic lights, menus, context menus, the Windows taskbar thumbnail) follow it too, because the app sets Electron's native theme to match.
