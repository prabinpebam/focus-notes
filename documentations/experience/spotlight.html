Spotlight: search and act

One keystroke to find any note, heading, sentence, setting, or command, and act on it without touching the mouse.

TL;DR

Ctrl/⌘+/ opens a centered, frosted panel modeled on macOS Spotlight and Raycast. It searches notes (titles, paths, headings, full text), folders, commands, and settings in one ranked list. Enter runs the default action; → or Ctrl/⌘+K opens quick actions for the selected result (open in a new window, copy link, move, rename, make public, delete…). Prefixes (> commands, # headings) and filters (is:private, in:essays/) narrow the search. Quick open, the command palette, and go-to-heading are all this same panel, opened in a different mode; Find in all notes is a side sheet of its own that Spotlight opens with its query (D-110). Covers SPT-01 to SPT-08 in the requirements. What's built says how far WP-4.2 goes today (D-109).

Mod+K doesn't open Spotlight: in the editor it's the link key, as in every major editor. Inside an open Spotlight it shows the selected result's actions, as in Raycast. On keyboard layouts where / needs Shift, Mod+Shift+P always opens Spotlight. Pressing a mode's shortcut again while Spotlight is open switches mode and keeps the query.

Anatomy

Panel
Centered horizontally, about 20% from the top, 640 px wide (full width minus margins on small screens). Uses the frosted surface from the theme, and the canvas behind it dims slightly. The panel is built once and kept hidden, so it opens instantly.
Field
Has a mode chip on the left (All, Notes, Commands, Headings). Backspace in an empty field returns to All. A clear button appears when there's text.
Results
Grouped and labeled (Top hit, Notes, In notes, Folders, Commands, Settings, Actions). Each row shows an icon, a title with the matching characters in bold, details (path, visibility, snippet), and on the right either the shortcut or the current state.
Action panel
→ or Mod+K slides in the list of actions for the selected result, the same way Raycast does. ← or Esc goes back.
Preview (desktop, P1)
In wide windows, the selected note's first lines appear in a pane on the right, like macOS Spotlight's preview.
Footer
Key hints for the selected result: the default action, the alternative action, Actions, and Close.

Commands show their state

Toggles show the current value right in the row ("Focus mode · On", "Theme · System"), so Spotlight doubles as a quick settings panel. Running one leaves Spotlight open and updates the row. Esc closes it when you're done.

Ranking

  1. Match quality

    Exact title, then title prefix, then the start of a word, then a fuzzy title match, then headings, then full text. Typos are tolerated (one edit for 4 to 7 characters, two for longer queries), and two neighbouring letters swapped count as one ("lenght"). Case and accents don't matter: "cafe" finds "Café". Every word must match; as you type, the last one may be the start of a word.

  2. Frecency

    How recently and how often each note was opened and each command was run, decaying with a half-life of one week. It is kept per device and never synced; for now it lives in memory and starts again with the app (D-109).

  3. Context

    A small boost for notes in the current note's folder, and for commands that apply to the current selection (for example, table commands when the caret is in a table).

  4. Top hit

    The single best result across all groups is shown first and selected, so Mod+/, a few letters, and Enter is enough most of the time.

Empty and no-result states

  • Empty field: the five most recent notes, then three suggestions (New note, Toggle focus mode, Switch theme), then every action the app has, its commands and then its settings, each group by name, with their shortcuts and states: Spotlight is the action center (D-111), so Mod+/, the arrow keys, and Enter reach and run any of them. A "Type ? for help" hint shows below.
  • No match: "Create note "query"" and "Find "query" in all notes" are always offered, so Enter still does something useful.
  • Index still building (first launch on a big workspace): titles are searchable right away, and a quiet "Indexing 1,240 / 5,000" line shows in the footer.

Index and privacy

  • The index is MiniSearch (MIT), built in a Web Worker so typing never stutters. It has two parts: titles (each note's title, file name, folder, and front-matter id; every heading; folders; commands and settings with their synonyms), answered on every keystroke, and full text, with a snippet around the first match. Paths are searched relative to their root (essays/on-focus.md), never the folders above it.
  • Titles first. Every note's title, path, and folder are in the index as soon as the workspace is listed. Each note's text is then read a few at a time and indexed in short slices between questions, so a search never waits behind indexing, and "Indexing 1,240 / 5,000" can say how far it's got.
  • Kept current by the workspace model. Creating, deleting, moving, and renaming notes and folders reach the index as they happen; a moved or renamed note keeps its indexed text, so it isn't read again. The app's own saves are indexed from the text it already has, and changes made outside the app (another editor, git pull) are read again when the desktop's file watcher reports them.
  • When it starts. After the first note is open, never before, so it never delays the caret. The start-up warm-up (Performance and quality) is where it belongs once that exists.
  • Desktop: built from the workspace's roots on disk: private/notes/ and notes/, or the one folder before setup.
  • Web: this browser's own notes, the instance's public notes (read from its site), and its private notes only while they're unlocked. Locking drops them from the index before it answers anything else, and a private note whose reading finishes after the lock is thrown away.
  • Only on the device, and only in memory. The index is never uploaded, logged, or sent anywhere, and it isn't stored: it's rebuilt each time the app starts or the page loads, and goes when it closes (D-107). The worker has no network code; with network monitoring on, indexing and searching make no request beyond reading the notes themselves (on the web, files of the site itself).
  • Trusted Types. The worker is a file of the app itself, loaded through a search-worker policy that lets exactly that one address through; scripts still have no policy at all (Security and privacy).

Accessibility

  • Uses the ARIA combobox and listbox pattern: focus stays in the field, and the selected result is set with aria-activedescendant.
  • Groups are labeled. The number of results is announced politely after typing pauses.
  • The panel traps focus while open and returns focus, caret, and selection exactly to where they were when it closes; when what had focus is gone (a dialog Spotlight replaced), focus goes to the note.
  • Every action in Spotlight is also reachable with a pointer, through the toolbar, the ⋯ menu, or context menus.

Acceptance checks

  • SPT-01: Mod+/ opens Spotlight from the editor, the Files panel, and Settings. Mod+K never does: it always opens the link editor.
  • SPT-02, SPT-04: "foc" returns a command, notes, a full-text snippet, and create/find actions, as in the figure, and the command row shows its live state.
  • SPT-03: → on a note lists the actions in the table above. Make public asks for confirmation and then moves the note.
  • SPT-07: The performance budgets hold on the 5,000-note test workspace.
  • SPT-08: With network monitoring on, searching private notes makes no network requests.
