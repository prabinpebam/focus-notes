Design · Components

Tables

Table editing modeled on Microsoft Loop: hover to insert, handles to move and act, drag to select, all saved as a plain GFM table.

TL;DR

Insert with /table. A table fills the text column in equal columns. Hover any inner row or column border to get a + insertion point (D-182, as in Microsoft Loop). Hover a row or column to get its handle: click for a menu (insert, move, sort, align, clear, delete), or drag to reorder. Hover the bottom or right edge for + New row and + New column. Drag across cells to select a range, then format, clear, copy, or paste over it. Loop's interaction patterns are kept. Loop features that GFM can't store (column types, widths, formulas, views) are explicit boundaries. Component IA-CMP-TABLE serves UC-TABLE-01 to UC-TABLE-08. Built in WP-1.5; where it differs from this design, D-96 says why.

Inserting a table

  • /table (or "grid", "columns") from the slash menu inserts a 3 × 3 table: a header row plus two body rows, with the caret in the first header cell (UC-TABLE-01).
  • Typing a GFM header row and delimiter row (| a | b | then |---|---|) converts to a table on Enter.
  • Pasting a spreadsheet range or an HTML table on an empty line creates a table of that shape (UC-TABLE-06).

Anatomy

Frame
1 px color.border outer border with radius.small corners, and 1 px inner rules. No zebra striping (calm). Cell padding is 8 px × 12 px.
Header row
Always present (GFM requires it). color.surface fill and semibold text. It can be emptied but not deleted or moved into the body. An empty header cell shows its column's name ("Column 3") in placeholder color, so its column is named for screen readers too; the name isn't part of the note and is never saved (A11Y-01, D-100).
Column handle
A 40 × 18 px pill with three dots, centered 8 px above the hovered column. Its hit area is 32 px tall. Pressed and focused states use the accent.
Row handle
An 18 × 32 px pill with three dots, 12 px left of the hovered row, in the gutter. Hit area 32 × 32 px.
Table handle
At the top-left corner where the handles meet. Opens the table menu and selects the whole table.
+ insertion point
A 22 px accent circle with a plus, at the left end (rows) or top end (columns) of the border. It appears at once when the pointer is within a 12 px band centred on any inner border (table.insertZone), anywhere along it or on the handles' side of it, and is drawn together with a 3 px accent line across the table at that border. A press on the + inserts in that frame; a click (press and release without moving) on the line, whose hit area is 4 px (table.insertLineHit), inserts too, and a click beside it still places the caret. Shown over the note, so it never shifts the text.
Edge bars
Dashed bars along the bottom edge ("+ New row", 30 px tall) and right edge ("+", 28 px wide), shown while the pointer is over the table or within 24 px below or right of it.
Cell selection
Selected cells get a color.selection fill, and the range gets a 2 px accent outline. The active cell keeps its caret.

Menus

MenuItems

RowInsert above · Insert below · Move up · Move down · Duplicate row · Clear contents · Delete row. Header row: only Insert below and Clear contents.
TableSelect table · Copy as Markdown · Copy as tab-separated text · Duplicate table · Delete table

Destructive items are last, separated by a divider, and undoable without a dialog (the danger color waits for menu items to have tones, D-96). Deleting the last body row leaves an empty one, because a table always has at least one; deleting the last column deletes the table. A move that can't happen (the first column left, the first body row up) is shown disabled.

Keyboard

The full table keymap is in Keyboard shortcuts → Tables. In short: Tab and Shift+Tab move between cells (Tab in the last cell adds a row), Enter and Shift+Enter move down and up, Mod+Enter adds a row below, Mod+Shift+↑/↓ moves a row, and Esc enters cell selection mode. In cell selection mode, arrows move the selected cell, Shift+arrows extend the selection, Backspace clears, Enter or Esc goes back to typing, and Shift+F10 (or the Menu key) opens the cell menu for the selected cells, rows, or columns, so every pointer action has a keyboard path. Enter in the last row leaves the table onto a new line below it.

Copy, paste, and sort

ActionBehavior
Copy a cell rangeThe clipboard gets tab-separated text (pastes into spreadsheets), a GFM Markdown table (text/markdown, its first copied row the header), and HTML (pastes into documents).
Paste a range into a cellFills from that cell (or the selected range's top-left) right and down, overwriting, and adds rows and columns if the range doesn't fit. One undo step, and the pasted range stays selected. A toast says "Pasted 5 × 4. Table grew by 2 rows." A range is a spreadsheet's HTML table, or text whose lines all have the same number of tabs (not all leading, so indented code stays text).
Paste a range on a lineBecomes a table of its shape, its first row the header.
Paste text with line breaks into one cellThe line breaks become spaces (UNSUP-TABLE-01), with a toast the first time.
Sort A→Z or Z→A (TBL-09)From the column menu, or the cell menu's Sort column A→Z and Sort column Z→A (Shift+F10), for the column of the handle or the caret. Reorders the body rows once by that column's visible text, in natural order: numbers (-3, 2.5, 1,200) by value and before text; ISO dates (2026-10-16) by date; text ignoring case and accents, with numbers inside it by value (item 2 before item 10). Empty cells go last in both directions. Rows that compare equal keep their order (a stable sort), so sorting by a second column and then the first works as people expect. Each row moves whole, with its formatting; the header and the alignment stay. The caret stays in its cell, which moves with its row. One undo step, announced as "Column 2 sorted A to Z". A table already in that order isn't changed and adds no undo step. Nothing is remembered as a "sorted view", because Markdown keeps only the order (DD-TABLE-05, D-160).

Size and wide tables

  • Column widths are automatic, based on content, with text wrapping inside cells. There's no column resizing, because GFM can't save widths (UNSUP-TABLE-03).
  • A table may grow wider than the reading column, up to layout.wideContent, centered on the column so its first cells stay near the text. Not built yet: in WP-1.5 a wide table scrolls sideways inside the reading column (D-96).
  • Beyond that, it scrolls sideways inside its frame. A soft fade on the edge shows there's more (not built yet), and the first column doesn't stay pinned. Arrow-key navigation scrolls the active cell into view.

A GFM pipe table with padded, aligned columns (TBL-06). Alignment markers come from the column menu's Align (TBL-04): left is :---, center :---:, right ---:, and none ---. An edited table's delimiter row carries each column's marker, and reopening it gives the same alignment; an untouched table keeps its own markers byte for byte, however short (:-) or long (the round-trip corpus's 26-table-alignment.md). Pipes in cell text, code included, are escaped as \|. A cell holds one line of inline content: the editor never lets a line break or a second paragraph into it, so nothing needs <br>. Untouched tables are written back exactly as they were (round-trip fidelity).

With focus mode, find, and touch

  • Focus mode: the bright row is the caret's wrapped line inside its cell, spanning the canvas width (see Focus mode → Edge cases). Handles and insertion points draw above the mask.
  • Find: matches in cells are highlighted the same way, and the current match's cell scrolls into view.
  • Touch and pen: handles show for the row and column of the focused cell (no hover). Tapping a handle opens its menu, and long-pressing starts a drag. + insertion points appear on the focused cell's edges. In WP-1.5, the handles show for the focused cell and drag with a pen; long-press and the edge insertion points on touch come with the touch work (D-96).

Accessibility

  • A native table with th header cells, so screen readers announce headers as people move between cells.
  • Handles are buttons named for what they control ("Column 2, Owner, options" or "Row 3 options"). Insertion points are named "Insert row between rows 2 and 3".
  • Structural changes are announced politely ("Row inserted below row 2", "Column moved to position 1", "Column 2 sorted A to Z").
  • The cell menu (Shift+F10, the Menu key) reaches every action the handles, insertion points, and edge bars do. Menus open with their first item focused and return the caret to the note when they close.
  • The hover tint and insertion line are never the only signal: the menus and keyboard paths do everything they do.
