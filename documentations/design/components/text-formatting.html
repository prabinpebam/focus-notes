Design · Components

Text formatting

A simple contextual toolbar that appears where you selected, plus the link editor, slash menu, and block handle.

TL;DR

Select text and a small frosted toolbar appears just above it with six controls: Turn into ▾, Bold, Italic, Strikethrough, Code, and Link. That's everything Markdown can store for a selection, and nothing more. It never covers the selection, hides as soon as you type, flips below the selection near the top of the window or on touch screens, and is fully usable from the keyboard (⌥F10 / Alt+F10). Links get an inline editor and a hover card. The toolbar, link editor, and hover card are built (WP-1.2, with the deviations in D-91). / opens a filtered block menu from the block registry, keyboard-complete while focus stays in the note (WP-1.3, D-93). A handle in the margin moves and converts blocks. Components IA-CMP-FORMAT, IA-CMP-LINK, IA-CMP-SLASH, and IA-CMP-HANDLE serve UC-FMT-01 to UC-FMT-05 and UC-BLOCK-01 to UC-BLOCK-03.

Contextual formatting toolbar

IA-CMP-FORMAT. Serves UC-FMT-01, UC-FMT-02, UC-FMT-04, UC-TABLE-07. The owner asked for formatting through a "simple contextual toolbar". Simple here means one row, six controls, no ⋯, and no settings.

It's composed in the canvas view document rather than as a compound, like the find bar (D-76): a Positioner anchored to the selection holds a frosted Surface (key scope formatToolbar) with a ToolbarRow of a text MenuButton, IconButton toggles, and a toggle Button. The editor surface reports what the selection holds (the format event), and vm.format says what to show.

Anatomy

Container
Frosted popover (layer 2), radius.popover, space.xs (4 px) padding, 32 px controls (size.controlM, the same buttons as the trigger's toolbar), 4 px between controls, a 1 px divider after Turn into and before Link. About 320 px wide at the default UI scale.
Turn into ▾
A text button showing the current block type ("Text", "Heading 2", "Bulleted list", or "Mixed" for several types). It opens the Turn into menu below it.
Mark toggles
Bold, Italic, Strikethrough, Code. Icon buttons, 32 × 32 px, Fluent Regular icons on a pressed fill when on. Their tooltips include the shortcut.
Link
Icon and the word "Link", because it opens something rather than toggling. Pressed when the selection is entirely inside one link, where it opens the link editor pre-filled.

Placement

  1. Anchor

    The first line rectangle of the selection (its top and horizontal extent), and the last line's bottom. A selection that starts above the visible area flips the toolbar below its last line.

  2. Above by default

    Centered on the anchor's horizontal middle, with its bottom 8 px above the anchor's top.

  3. Flip below

    If that would overlap the 44 px top band or the trigger, or on touch screens, it goes 8 px below the selection's last line instead.

  4. Clamp

    Kept at least 12 px (space.m) inside the window's edges. While the whole selection is scrolled out of view, the toolbar hides, and it comes back with it.

States and behavior

  • Pressed when the whole selection has that format. Mixed (part of the selection has it) shows a lighter fill (aria-pressed="mixed"), and clicking applies the format to all of it, as Word and Google Docs do.
  • Each click is one undo step. The selection stays the same, so several formats can be applied in a row.
  • The toolbar sits above the focus-mode mask and is never dimmed.
  • Mod+U isn't in the toolbar (UNSUP-FMT-01). The toast that explains Markdown has no underline isn't built yet (D-91).

Keyboard and accessibility

  • ⌥F10 / Alt+F10 moves focus into the toolbar: to Turn into the first time, then back to the control used last. This is the established rich-text-editor convention, since Tab already indents lists.
  • ←/→ move between controls, Home/End jump to the ends, and Enter or Space activates. ↓ on Turn into opens its menu.
  • Esc returns focus to the text with the selection unchanged. A control activated from the keyboard keeps focus in the toolbar; one clicked with the pointer puts the caret back in the text.
  • The toolbar has role="toolbar" and aria-label="Text formatting". Toggles use aria-pressed (mixed for partial). Opening it doesn't move focus or announce anything, so screen-reader users aren't interrupted mid-selection.

Link editor and hover card

IA-CMP-LINK. Serves UC-FMT-03. Both are composed in the canvas view document: the link editor is a Positioner on the selection with a frosted Surface (key scope linkEditor), and the hover card is a Positioner on the link, placed below it.

MomentDesign
Create (Link button, or Mod+K)With a selection, the toolbar turns into a one-line editor in the same spot: a URL field (focused, and filled in when the selection is in a link), [Apply] and [Cancel]. The selection stays highlighted while the field has focus. Enter applies and Esc cancels, both keeping the selection. With nothing selected, Mod+K opens the same editor at the caret with an extra Text field and inserts a new link.
Paste a URL over selected textMakes a link right away (Notion, Google Docs, Slack) when the clipboard holds one http, https, or mailto address. Mod+Z straight after leaves the address itself instead, which links to itself as a typed address does.
Type or paste a bare URLBecomes an autolink when followed by a space or Enter, saved as <https://…>. Typing [text](url) makes a link too.
Hover a link (500 ms) or put the caret in itA small hover card below the link: the shortened address (no scheme or www., at most 34 characters), then [Open], [Copy], [Edit], [Remove]. It leaves after 200 ms when the pointer moves away, unless the pointer is on the card. It isn't shown while typing, or with the toolbar.
Open a linkMod+click, or [Open] on the card. A plain click places the caret, because this is an editor (in a read-only note, a plain click opens it). Only http, https, and mailto links open, always through the shell: the desktop app asks the main process, which checks the address again and calls the default browser; the web app opens a new tab with noopener. The app window never navigates. [Open] is disabled for other links, and links to other notes don't open in the app yet (D-91).
Link to another notePlanned with Spotlight's index (M4): typing in the URL field will also search note titles and insert a relative Markdown link. Not built yet (D-91).
Invalid addressShown inline under the field and announced: "Use a full web address, like https://example.com." The field stays open and focused. A bare domain gets https:// and a bare email address mailto:; any other scheme (javascript:, file:, data:) is refused.

Slash menu

IA-CMP-SLASH. Serves UC-BLOCK-01, UC-BLOCK-02, UC-TABLE-01. Built in WP-1.3; where it differs from the first design, D-93 says why.

  • Opens when / is typed at the start of a block or after a space or line break. It doesn't open inside a word, so and/or stays text, and it doesn't open in code blocks or inline code (or, once tables ship, in table cells).
  • Placement: a frosted popover 8 px below the /, lined up with it, above it when there's no room below, and kept inside the window. 320 px wide, showing about 8 rows before it scrolls.
  • Rows come from the block registry, so a block registered later (Table, Image, Gallery) appears by registration alone. In order: Text (Text, Heading 1–3, Quote), Lists (Bulleted, Numbered, To-do), Insert (Code block, Divider, Table; Table joined by registration in WP-1.5). There are no group headings. Each row has its icon, its name, a one-line hint on the active row only, and its Markdown shortcut on the right (##).
  • Only valid blocks: the menu offers only blocks that can go where the / is, so a heading isn't offered on a list item's first line (DD-FMT-08).
  • Filtering: each word typed after / must start a word of the block's name or synonyms ("h2", "title", "checkbox" → To-do). With no match: "No blocks match ‘xyz’. Press Esc to keep the text." A space right after / closes it, and a space when nothing matches hides it until a match comes back.
  • Keyboard: focus stays in the note, which points at the active row (aria-activedescendant). ↑/↓ move and wrap, Enter or Tab inserts, and Esc closes it and leaves the typed /query as text. Backspace past the / closes it. With nothing matching, Enter and Tab do what they always do. The list is also a tab stop that takes the same keys, so a scrolling list can be used on its own.
  • Pointer: pointing at a row makes it active, and clicking inserts it. Focus never leaves the note. Clicking elsewhere closes the menu.
  • Result: the /query goes, and the current block becomes the chosen block, or, if it has other text, the chosen block goes below it (the space typed before the / goes too). The caret lands inside the new block (in a table, the first header cell). One Mod+Z brings back the typed /query.

Block handle

IA-CMP-HANDLE. Serves UC-BLOCK-03. Priority P1. Built on the editor's own block commands (D-160) rather than Tiptap's DragHandle, so a drag, a menu item, and a key run the same move.

  • Which block: the one the pointer is over, as the block keys count them (D-115): a list item, or else a top-level block (a paragraph, heading, quote, code block, divider, or table). A table has its own handles (its table handle duplicates and deletes it, and Mod+Shift+↑/↓ moves it), so the grip doesn't show beside a table, where it would crowd the row handles.
  • Where: in the left gutter, 24 px outside the reading column, level with the block's first line. A six-dot grip, 20 × 24 px visible, with a 32 px hit area.
  • When: shown while the pointer is over the block (fade in 80 ms), and for the caret's block during keyboard block-selection mode. Never shown while typing: a key typed hides it until the pointer moves again. On touch screens it's shown for the focused block only.
  • Click: pressing answers at once, in the next frame (the grip turns the accent color); releasing without moving opens the menu below the grip with its first item focused, and the block it acts on is tinted with the selection color, while the caret stays where it was: Turn into ›, Duplicate (Mod+D), Move up (Mod+Shift+↑), Move down (Mod+Shift+↓), Copy link to block, and, after a divider, Delete (Mod+Shift+K). A move that can't happen (the first block up) is disabled. Copy link to block is offered for headings, because Markdown can only link to a heading (note.md#its-slug, GitHub's slug); for other blocks it's left out. Esc closes the menu and puts the caret back where it was.
  • Drag: pressing and moving the handle 4 px starts a drag. The block is tinted with the selection color, and a 2 px accent drop line shows where it will land, between blocks only (a list item between the items of its list). The line follows the pointer within a frame (PRF-14). Near the window's top or bottom edge the note scrolls automatically. Releasing moves the block as one undo step, with the caret at its start; Esc or releasing where it already is changes nothing.
  • Keyboard path: Shift+F10 or the Menu key, outside a table, opens the same menu at the caret's block, the grip showing beside it; and every item has its own key (Mod+Shift+↑/↓, Mod+D, Mod+Shift+K, and the Turn into keys), so the handle is never the only way. Block selection mode (Esc while typing) selects the block for the same keys (D-160).
  • As built (WP-8.1, D-160): the BlockHandle host component, with pointers (a mouse or a pen). Not yet: the grip for the focused block on touch screens, and the grip showing beside the blocks block selection mode selects.
  • Accessibility: the handle is a menu button named for its block ("Paragraph options", "Heading 2 options"), out of the Tab order because it shows only on hover and Shift+F10 opens the same menu. Its menu, like the other menus over the note, ends the note's auto-scroll as it opens and follows its grip as the note moves (DEF-21). Moves are announced politely ("Block moved", "Block duplicated", "Block deleted").
