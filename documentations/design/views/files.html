Files panel

Create, find, rename, move, delete, and restore notes and folders, with nothing broken and nothing lost.

TL;DR

A floating left sheet over the canvas. It has Private and Public sections, a filter field, New note and New folder buttons, and Recently deleted at the bottom. Rows show note titles, and the current note is revealed and selected. Everything is direct: rename inline, drag to move (or cut and paste, or Move to…), multi-select to act in bulk. Every operation shows in the tree at once, then becomes one Git commit with an Undo toast, and links in other notes are updated automatically. Deleting a single private note doesn't ask, because it can be undone and restored. Deleting folders, many items, or public notes asks first. View IA-VIEW-FILES serves UC-FILE-01 to UC-FILE-10. What's built lists what works today and what arrives with Git (D-94).

It opens with the current note revealed (ancestor folders expanded) and focused, so ↑/↓ works straight away. Expanded folders are remembered per device.

Anatomy

Sheet
Frosted, 320 px wide (layout.sheetFiles), floating with the same inset from the window's top, left, and bottom (space.l, 16 px), so it's vertically centered, with radius.sheet on every corner and a uniform 16 px padding inside (D-111). It never covers the trigger: in a window too narrow to fit beside it, it gets narrower (down to layout.sheetMin, 200 px), and only then moves its inset below the trigger, still the same on all three sides. Rows have a 2 px gap between them, and the list fades over 50 px at a top or bottom with more to scroll to. The canvas behind it isn't dimmed, so the note stays readable.
Header
The title "Files" (20 px), the pin (Pinning), a sort button (⇅: Name or Last changed; folders stay first, a folder sorts by its newest note, and the app's own saves don't move rows, D-175), and two icon buttons, New note (Mod+N) and New folder (Mod+Shift+N), each named, with its shortcut in its tooltip (D-123). With several items selected, the header changes to "3 selected" with Move to…, Make public/private, Delete, and a Clear selection button.
Filter field
Filters the tree by name as you type, keeping the ancestors of matches. It doesn't search inside notes: the empty-result line offers "Search inside notes with ⌘/ or Ctrl+/".
Sections
Private first, because it's the default for new notes (D-05), then Public. Each has an uppercase 13 px label and a count on hover, and can be collapsed.
Rows
32 px tall (44 px on touch). 16 px indent per level. A chevron for folders, the note's title, and on hover, on the focused row and on selected rows, the time it last changed ("2 h") and a ⋯ button that opens the row's menu. Public notes add a small status: Live, Publishing…, or Not published.
Footer
Recently deleted · n, which opens that list in place.

Names and titles

  • Rows show titles, not file names. The title is the note's first H1, falling back to the file name. The file name shows in the row's tooltip and in Rename.
  • The file name follows the title until the note is published (FIL-07). Typing the title "On focus" saves as on-focus.md. Once published, the file name is frozen so the public URL stays stable (D-08). It can still be renamed on purpose, with a URL warning. A name follows its title when it's the title's name, a numbered clash of it, or untitled; a name chosen by hand (Welcome.md for "Welcome to Focus Notes") is kept, and so is the name of a note without an H1 (D-92).
  • File name rules: lowercase; letters, marks, and numbers in any language are kept, with . and _; spaces, punctuation, and symbols (including emoji, and the characters Windows, macOS, or Linux reject: \ / : * ? " < > | and control characters) become one hyphen; leading and trailing dots, spaces, and hyphens are removed. Reserved Windows names (CON, NUL, COM1, …, also before a dot) get -note. At most 80 characters and 240 bytes, cut at whole characters. A clash adds -2, -3, ignoring case and Unicode form. A title that leaves nothing is untitled.
  • Changing only the capitalization of a name works on case-insensitive file systems: the app renames in two steps through a temporary name.

Renaming

  • F2 (Windows and Linux), Enter (macOS), ⋯ → Rename, or a slow second click on a selected row.
  • Note: the field edits the title. The H1 inside the note is updated, and the file name follows if it isn't frozen. For a published note, the field shows "Also rename the file and change its public link (the old link will redirect)", unchecked by default.
  • Folder: the field edits the folder name.
  • Enter saves and Esc cancels. Links to the note, or to anything in the folder, are updated in the same commit (FIL-09), and the toast says "Renamed to “Plans”. Updated links in 4 notes." with Undo. Links that follow lists exactly what changes.

Moving

Drag and dropDrag one row or a selection. A ghost shows the first title and a count ("3 items"). Drop onto a folder or a section label (the root of that section). Folders expand after 600 ms of hovering, and the list scrolls near its edges. Dropping into its own subfolder isn't allowed (not-allowed cursor, no outline).

Across Public and PrivateAny of these into the other section changes visibility, so it shows the visibility confirmation first (UC-SHARE-01). Nothing moves until confirmed.

Every move is one commit that updates links. The toast says "Moved 3 items to “drafts”. Updated links in 2 notes." with Undo. The list keeps the moved items selected and scrolls to them.

Changes show at once. Moving, deleting, creating, and duplicating update the tree within 100 ms, before the files are written and committed (PRF-09). The affected rows show the saving sign until the commit finishes, and only then does the toast appear. If the operation is refused, the tree goes back to how it was and the toast says why. Visibility confirmations still come first: nothing moves on screen until they're answered (Desktop and Git → Changes shown before they're saved).

Deleting and restoring

What's deletedAsks first?Why
One private noteNo. The toast "Deleted “Spec ideas”." offers Undo.Fast, and fully recoverable (Undo, then Recently deleted for 30 days).
A folder with notes, or 5 or more itemsYes: "Delete “drafts” and the 12 notes in it?" [Cancel] [Delete 12 notes]The scale isn't obvious from the row.
Any public noteYes: "Delete “About”? Its public page will go offline after the next publish." [Cancel] [Delete and unpublish]It changes what other people can see (CP-SHARE-01).
An empty folderNoNothing to lose.

Recently deleted (FIL-10) lists notes deleted in the last 30 days, found from Git history. Notes are grouped by day and show their title, original folder, and time. Restore puts a note back where it was (or in its section's root if the folder is gone), and Restore to… opens the Move to picker. The list explains: "Notes stay in Git history even after 30 days. Older ones can be recovered with Git." Nothing here deletes permanently.

Row menu

Every row has a menu (IA-CMP-CONTEXTMENU, D-162): right-click it, press its ⋯ button, or press Shift+F10 or the Menu key on the focused row. It's the app's own themed menu, at the pointer or under the ⋯ button; Esc closes it and focus goes back to the row. Right-click on a row outside the selection selects that row first; on a selected row, the menu acts on the whole selection.

Pinning

The pin in the header (Keep Files open, Mod+Alt+P, also in Spotlight and ⋯) keeps the panel open while you write (D-161). Pinned, it's the same floating sheet, with its inset, corners and shadow: never docked to the window's edge.

  • It stays. Opening a note, clicking the canvas, and Mod+O leave it open. Esc in the panel and Mod+O move focus between the tree and the note. The pin again (Unpin Files) unpins it; then it closes as usual.
  • The text moves clear of it. The reading column is laid out to the right of the sheet, space.l after its edge, centred in that space when the measure fits; narrower windows narrow the column down to cmp.editorSurface.pinnedColumnMin (360 px), and below that the sheet floats over the text as it does unpinned. The column moves over motion.sheet (at once with reduced motion), and the line with the caret keeps its height in the window.
  • Remembered on this device (state.json): a pinned panel opens at launch, without taking the caret. Both apps.

Selection

  • Click selects one item, Mod+click adds or removes, and Shift+click selects a range. Shift+↑/↓ extends the selection, and Mod+A selects everything visible.
  • With several items selected, the header becomes an action bar. Right-click offers the same actions for the selection; right-click on a row outside it selects that row first (Row menu).
  • Opening a note (Enter on Windows, ⌘↓ on macOS, or a double-click) acts on the focused row only.

Accessibility

  • The list is a tree with aria-multiselectable. Rows carry aria-level, aria-expanded, and aria-selected, and their accessible names include visibility ("About, public, live").
  • Type-ahead jumps to matching rows. Arrow keys follow the standard tree pattern.
  • Operations are announced politely ("Moved 3 notes to drafts"). Drag and drop always has a keyboard equivalent (cut and paste, Move to…).
  • In compact windows (under 600 px), the sheet is full-width, and long-press opens the row menu.
